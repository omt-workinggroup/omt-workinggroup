# OMT WORKING GROUP

A free tech library for IT lovers: developers, network and telecom engineers, sysadmins, cloud, security and data people, and students. Find free books, courses, standards and guides on programming, networking, 4G/5G, Linux, cloud and DevOps, cybersecurity and data/AI, learn Microsoft Office, and ask **OMT AI** to find resources or explain difficult concepts.

Built with plain **HTML, CSS and JavaScript** (ES modules, no framework, no build step), plus one serverless function for the AI.

## What OMT is

OMT WORKING GROUP is a **discovery platform, not a publisher**. We don't write or host books: we bring together free and official tech resources and search millions of books on Google Books, Open Library and Project Gutenberg, then send readers to the official source to read, borrow or buy.

## Pages

- `index.html` is the company homepage (who we are, services, mission and vision, values, deployment process, training, contact). It uses its own small stylesheet, `css/company.css`, and `js/pages/company.js`.
- `resources.html` (also served at `/resources`) is the front page of the resource library: a phone splash and the desktop shelf, with an **Enter** button into `home.html`.
- `home.html` is the library home people land on after **Get started**: search, tracks, featured books, Office and OMT AI.
- Type is Source Serif 4 (headings) and IBM Plex Sans and Mono (text and labels), self-hosted in `assets/fonts/` under the SIL Open Font License.

## Access labels

| Access label | What it means | Can you read/download here? |
|---|---|---|
| **Free & open** | Public domain or openly licensed (OpenStax, Project Gutenberg, MIT OCW…) | Read free on the official source |
| **Official source** | Free on the provider's own site (Microsoft Support, GCFGlobal, Harvard CS50) | Opens the official site |
| **Buy or borrow** | Copyrighted books | Description only, with links to Open Library to find an edition or borrow |

The site never hosts books or links to unauthorised copies, and an automated test enforces this.

## Run locally

You need Node.js 20 or later.

```bash
npm install
npm start            # http://localhost:8080  (AI assistant runs in demo mode, forms show an error)
```

Open the site through a web server, not by double-clicking the HTML files: browsers block `fetch()` on `file://` URLs.

To run the serverless functions too:

```bash
npm install -g vercel
cp .env.example .env.local   # then fill in the values
vercel dev                   # http://localhost:3000, with /api/ai and /api/contact live
```

## Configure the AI assistant

The assistant works in two modes:

- **Demo mode** (no API key): prepared explanations for about 20 common topics (VLOOKUP, IF, PivotTables, Word styles, mail merge, slide design, databases, study techniques, Python basics…), real catalogue search, and live Open Library search. Every demo answer is labelled *"Demo response: prepared answer, not generated by an AI model"*.
- **Live mode**: answers are generated by Claude through the Vercel Function `api/ai.js` (logic in `server/ai.mjs`).

To switch on live mode:

1. Create an API key at <https://console.anthropic.com>.
2. In Vercel: **Project › Settings › Environment Variables**, add `ANTHROPIC_API_KEY` (Production and Preview).
3. Redeploy. The badge on the assistant page changes from **Demo mode** to **Live AI**.

Optional variables (see `.env.example`): `OMT_AI_MODEL` (default `claude-opus-5-5`), `OMT_AI_EFFORT` (`low` by default, which keeps answers fast; hard questions such as debugging, proofs or long pasted code are raised to `medium` automatically), `OMT_AI_WEB_SEARCH` (`off` disables web search) and `OMT_AI_RATE_LIMIT` (requests per visitor per 10 minutes, default 40).

What OMT AI can do (`assistant.html`, `js/pages/assistant.js`):

- **A full chat app.** A chat-history rail (search, grouped by date, delete, Ctrl+Shift+O for a new chat). Chats are saved in the visitor's browser only, never on the server.
- **Answers anything**, with OMT's tech and book know-how on top. Answers render headings, tables, quotes, nested lists and syntax-highlighted code with copy buttons (`js/assistant/markdown.js`, `highlight.js`).
- **Draws.** The model can answer with ```` ```mermaid ```` diagrams, ```` ```chart ```` JSON (bar, line, pie, donut) or an ```` ```svg ```` drawing. `js/assistant/viz.js` renders them: Mermaid is self-hosted in `assets/vendor/` and loaded only when a diagram appears; charts are drawn locally as SVG; model-drawn SVG is shown through `<img>`, so no script in it can run. Every picture can be enlarged and downloaded.
- **Reads files.** Images (resized in the browser), PDFs (up to 3 MB) and text or code files can be attached, pasted or dropped. Images and PDFs are sent once, with their message, as Claude content blocks.
- **Searches the web** for current facts (Anthropic's web search tool, at most 3 searches per answer), and links the pages it used. If the account doesn't allow web search, the function retries without it.
- **Message tools:** copy, read aloud, regenerate, and edit-and-resend.

How the function works:

- **Streams the answer.** Text appears as the model writes it (newline-delimited JSON events: `status`, `delta`, `done`, `error`), with a stop button. Follow-up questions appear as tappable chips.
- **Searches books only when it helps.** Every question gets instant OMT catalogue matches; questions about books and learning also search Google Books, Open Library and Project Gutenberg (sources slower than 2.5 seconds are skipped, results cached for 10 minutes).
- **Grounded in the website.** The model may recommend only records from those results; the function drops any id that isn't in them. Links in answers are limited to those results, pages found by web search, well-known documentation sites, the site's own pages and book-search links; any other URL is shown as plain text.
- The system prompt enforces the copyright rules: no unauthorised copies, no long quotations, no claims to have read text it wasn't given.
- It validates every request (at most 40 messages of 24,000 characters, up to 4 attachments, body capped at 4.4 MB), applies per-visitor rate limiting, returns consistent JSON errors and never logs message content.
- The API key exists only in the server environment. It never appears in frontend code.

The AI provider is isolated in `server/ai.mjs`, so switching providers later means changing only that file.

## External books (Google Books, Open Library, Project Gutenberg)

- `/api/books?q=` searches all three sources at once (`server/books.mjs`). One source failing never breaks the others.
- **Library page:** "Search beyond our library" shows the results with access labels. Visitors can click **Add to OMT library** to suggest a book.
- **OMT AI:** in live mode the AI searches the same sources. Any external book it recommends is **added to the library automatically** and linked to its own page there.
- **Storage:** additions live in the Supabase table `public.library_additions`.
  - AI additions are approved straight away.
  - Visitor suggestions wait until you set `approved` to `true` in **Supabase › Table Editor › library_additions**.
  - The public can read approved rows only. Database checks restrict links and covers to the official source domains.
- **What readers can do:** read Project Gutenberg books in full, borrow Open Library books, and preview or buy Google Books titles. OMT never copies book files.
- **Optional:** set `GOOGLE_BOOKS_API_KEY` for higher Google Books limits.

## Deploy (Vercel)

The site is a static site plus two Vercel Functions in `api/`. `vercel.json` sets the security headers, caching and function timeouts. There is no build step.

1. Import the GitHub repository at <https://vercel.com/new>. Framework preset **Other**, no build command, output directory `.`.
2. Every push to `main` deploys to production, and every other branch gets a preview URL.
3. Environment variables (**Project › Settings › Environment Variables**):
   - `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` for the contact and copyright forms.
   - `ANTHROPIC_API_KEY` for live AI (optional).
4. The site runs on **https://omt-workinggroup.com** (DNS at Namecheap: an A record to `76.76.21.21`, and `www` as a CNAME to `cname.vercel-dns.com`, which redirects to the main domain). The HTML `<head>` tags, `robots.txt` and the sitemap use that address; to change it, replace it there and run `SITE_URL=https://your-domain node scripts/build-sitemap.mjs`.

### Form messages (Supabase)

The contact and copyright forms post to `/api/contact`, which stores them in the Supabase table `public.site_messages`. Row Level Security lets the public **insert only**: nobody can read, change or delete messages through the API. Read them in the Supabase dashboard (**Table Editor › site_messages**).

## Speed

- Every page preloads all of its JavaScript modules and the catalogue in parallel (`<link rel="modulepreload">`, generated by `node scripts/build-preload.mjs`; re-run it after changing imports).
- Links are prefetched when a visitor points at or touches them, and pages cross-fade with view transitions.
- Scripts, styles, images and the catalogue are cached by browsers and Vercel's CDN; book searches and library additions are cached at the edge.
- Library additions never hold a page up for more than 1.5 seconds and are kept in the tab for 5 minutes.

## Adding resources

Add an object to `data/resources.json`. The interface updates automatically.

```json
{
  "id": "unique-kebab-case-id",
  "title": "Title",
  "author": "Author or provider",
  "publisher": "Publisher",
  "year": "2024",
  "kind": "book | guide | template | tutorial | course",
  "category": "computer-science | business | study-skills | productivity | general | word | excel | powerpoint | access | outlook | presentations",
  "level": "beginner | intermediate | advanced",
  "formats": ["Online book", "PDF"],
  "accessType": "open | official | preview | paid | info",
  "license": "CC BY 4.0",
  "description": "One or two factual sentences.",
  "tags": ["search", "keywords"],
  "sourceName": "OpenStax",
  "sourceUrl": "https://… (official page)",
  "readUrl": "https://… (only for free, legal reading)",
  "featured": false,
  "added": "2026-10-15"
}
```

Rules (checked by `npm test`): ids are unique, every resource needs an `https` `sourceUrl`, `paid` books never get read links, OMT is never listed as an author, and no files are hosted.

Never invent metadata. Copy the title, author and year from the official source page.

### How the big catalogue was built (October 2026)

Most of the 1,000+ titles were added in bulk, but each one was still chosen by hand:

1. **Candidates** came from Open Library subject searches for every category (sorted by how many readers have the book on their reading log), a second round of title searches for networking, and Project Gutenberg's most-read public-domain books. Conference proceedings, course packs, workbooks, fiction in non-fiction categories and anything adult were filtered out automatically.
2. **Every candidate list was reviewed by hand** and each book placed in the category where it belongs (a security book found under "networking" goes to Cybersecurity).
3. **Titles, authors, years and access** come from the source record. Open Library's own reading status decides the label: public → *Free & open*, borrowable → *Free to borrow*, otherwise *Buy or borrow* with a link to the Open Library work page.
4. **Descriptions** are one factual sentence written by OMT AI for each book it knows; when it does not know a book, Open Library's description is used, and failing that a short line built from the book's subjects. Nothing is invented.
5. **Covers** are the source's cover image, reviewed on contact sheets; blank title pages, scans, foreign-language editions and wrong covers were rejected (those books show the styled poster instead). Covers are stored as 300 px WebP files in `assets/covers/`.

## Testing

```bash
npm test               # unit tests: catalogue rules, search, demo AI, Markdown safety, AI and contact functions (mocked)
npm run test:e2e       # browser test: 13 pages × 6 widths (320–1440px), no overflow or console errors,
                       # search, filters, favorites persistence, downloads, mobile menu, assistant demo
npm run check-links    # checks every external link and local file in the catalogue (needs internet)
```

Run `npm run check-links` before each deploy. External sites change their URLs over time, and the "Link not working? Tell us" link on each resource page lets visitors report problems.
