Network models split communication into layers. Each layer has one job and talks only to the layers directly above and below it. Knowing the layers helps you design networks and, above all, troubleshoot them.

The TCP/IP model

The Internet itself is built on the simpler TCP/IP model:

  • Application: OSI layers 5–7 (HTTP, DNS, SSH)
  • Transport: OSI layer 4 (TCP, UDP)
  • Internet: OSI layer 3 (IP)
  • Link: OSI layers 1–2 (Ethernet, Wi-Fi)

Encapsulation

As data goes down the stack, each layer adds its own header. An HTTP request becomes a TCP segment (with source and destination ports), then an IP packet (with IP addresses), then an Ethernet frame (with MAC addresses), then bits on the wire. The receiver strips the headers off in reverse order.

Troubleshooting bottom-up

  1. Physical: is the link up? Check cables, optics, signal and lights.
  2. Data link: are MAC addresses learned? Is the VLAN correct?
  3. Network: correct IP address and gateway? Does ping work? Check the route with traceroute.
  4. Transport: is the port open? Is a firewall blocking it?
  5. Application: does DNS resolve? Is the service running, and what do its logs say?
