1. Set up once

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

2. Start or copy a project

git init                      # turn the current folder into a repository
git clone https://github.com/user/repo.git   # or copy an existing one

3. The everyday loop

git status                    # what changed?
git add file.py               # stage a file (git add . stages everything)
git commit -m "Add login form validation"
git log --oneline             # history, one line per commit

Write commit messages that say what the change does, in the present tense: "Fix crash when list is empty".

4. Branches

git switch -c feature/search  # create a branch and switch to it
# ...work and commit...
git switch main
git merge feature/search      # bring the work into main

Branches let you try things without breaking the main code. On GitHub you usually push a branch and open a pull request instead of merging locally.

5. Share with GitHub

git remote add origin https://github.com/you/repo.git
git push -u origin main       # first push; afterwards just git push
git pull                      # get other people's changes

6. Undo safely

  • git restore file.py: throw away uncommitted changes to a file.
  • git restore --staged file.py: unstage a file but keep the changes.
  • git revert <commit>: create a new commit that undoes an old one. This is safe on shared branches.

7. Ignore files

List files Git should never track (build output, secrets, dependencies) in a .gitignore file, for example node_modules/ and .env.

Practice

Create a repository, commit a README, create a branch, change the README there, merge it back into main and look at git log --oneline --graph.
