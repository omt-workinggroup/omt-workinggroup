Database or spreadsheet?

A spreadsheet is great for calculations on one table. A database is better when you have related lists, such as students, courses and enrolments, and want to avoid typing the same information many times.

Tables, records and fields

  • A table stores one kind of thing (Students).
  • A record is one row (one student).
  • A field is one column (FirstName), with a data type such as Short Text, Number or Date/Time.

Primary keys

Every table needs a field that identifies each record uniquely: the primary key. A StudentID works well; names don't, because two people can share a name. Access can create an AutoNumber ID for you.

Design a small student database

TableFields
StudentsStudentID, FirstName, LastName, Email
CoursesCourseID, CourseName, Credits
EnrolmentsEnrolmentID, StudentID, CourseID, Grade

Enrolments links the other two: one student can take many courses and one course has many students (a many-to-many relationship, built from two one-to-many relationships).

Create the relationships

  1. Database Tools › Relationships.
  2. Add all three tables.
  3. Drag StudentID from Students onto StudentID in Enrolments; tick Enforce Referential Integrity.
  4. Do the same for CourseID.

Ask questions with a query

Create › Query Design, add the tables, then drag in FirstName, CourseName and Grade. Under Grade, type >=70 in Criteria to list students who scored 70 or higher. Click Run.

Forms and reports

A form makes data entry easier (Create › Form); a report formats results for printing (Create › Report).

Access is included with Microsoft 365 on Windows PCs only. On a Mac, you can practise the same database ideas with LibreOffice Base.
